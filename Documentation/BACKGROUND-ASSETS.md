# Background Assets — pre-launch speech model download (iOS)

The iOS app ships a **Background Assets** downloader extension so iOS fetches the speech models
*before the app's first launch*. A person installs the app from the App Store and the ~1.2 GB of
models (Parakeet, SenseVoice, Sortformer) are already downloading (or done) by the time they
open it — no first-run "Downloading speech model…" wait.

This is the **self-hosted, unmanaged** Background Assets flow (our files, on HuggingFace; our
manifest schema), not Apple-Hosted asset packs.

## How it works

1. The app declares `BAManifestURL` (+ the other keys below) in its Info.plist.
2. On install/update — before the app can launch — the system downloads the manifest from
   `BAManifestURL` and wakes **`BackgroundAssetsExtension`** (`ModelDownloaderExtension`),
   handing it the manifest's on-disk location.
3. The extension parses the manifest and returns a `Set<BADownload>` — one **non-essential**
   `BAURLDownload` per model file, each pointing at its `resolve/main` URL in the hosted repo,
   with its exact byte size and the shared App Group as the destination.
4. The system downloads the files. As each finishes, `backgroundDownload(_:finishedWithFileURL:)`
   moves it into the App Group at `…/BackgroundAssets/fctspeech/<model>/<relpath>`.
5. On the app's first launch, `SpeechModelStore.installStagedModels()` relocates the staged tree
   into the models root (`~/Library/Application Support/TranscriptionStudio/Models/fctspeech/`).
   Every engine's `prepare()` then finds its model present and skips the network.

The extension can't write to the app's own container (it isn't shared), so it parks files in the
App Group and the app moves them the last hop on launch. The staging layout mirrors the models
root, so the relocation is a straight per-file move.

## When the extension did not run

The Mac, a sideloaded or TestFlight build, and a person who opens the app before the pre-fetch
finished all reach the same place: an engine's `prepare()` calls `SpeechModelStore.ensureInstalled`,
which downloads only the files still missing (one `URLSession` download each, verified to the
manifest's byte size) and then loads. The front door offers the download on Wi-Fi first; "Later"
leaves it to the first job. A download interrupted partway keeps every finished file and fetches
the rest next time.

## The manifest

`Sources/App/BackgroundAssets/speech-model-manifest.json`, generated by
`scripts/gen-ba-manifest.sh` from a real installed copy of the three models. It names the hosted
repo and every file as `<model>/<relpath>` with its exact size; the first path component is the
`SpeechModel` the file belongs to, which is how one identifier walks a file from the server to the
engine that loads it.

**When a model changes:** install the new model locally, run the script, commit the manifest, set
`BAMaxInstallSize` in `project.yml` to the total it prints, and push the models **and** the
manifest to the hosted repo in the same change — the system fetches the manifest from
`BAManifestURL`, so a manifest naming files the repo does not yet hold fails every download.

## Info.plist keys (project.yml → the app target)

| Key | Value | Why |
|---|---|---|
| `BAManifestURL` | the manifest's `resolve/main` URL in the hosted repo | where the system fetches the manifest |
| `BAAppGroupID` | `group.com.fcttechnologies.TranscriptionStudio` | the shared staging container |
| `BAMaxInstallSize` | the manifest total | shown on the App Store |
| `BAInitialDownloadRestrictions` | essential allowance 0 | nothing gates launch |
| `BADownloadDomainAllowList` | `huggingface.co`, `*.hf.co`, `*.cloudfront.net` | the repo's own host and its CDN |

## Testing

`SpeechModelStoreTests` covers the pure layout (pending / staged / installed), the relocation,
the completeness check, and the download against a fake `URLProtocol` (only missing files fetched,
a wrong byte count refused). The extension itself only runs under the system; its logic is the
same layout and manifest code the tests cover.

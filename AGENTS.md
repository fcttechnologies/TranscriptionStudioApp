# AGENTS.md — Transcription Studio

Standing instructions for any agent working in this repo. Pointers only: read the file named, don't assume its contents.

- **Read first: [`README.md`](README.md)** (setup + the CLI), then [`Documentation/PROJECT_GUIDE.md`](Documentation/PROJECT_GUIDE.md) and, for the area you're changing, its own doc beside it.
- **Setup facts that bite:** the three speech models (Parakeet, SenseVoice, Sortformer) are FCTSpeech's, converted from their checkpoints in the sibling checkout `../FCTSpeech` and installed under `~/Library/Application Support/TranscriptionStudio/Models/fctspeech/<model>/`; the app downloads whichever is missing from the hosted repo named in `Sources/App/BackgroundAssets/speech-model-manifest.json` on first use. Regenerate that manifest with `scripts/gen-ba-manifest.sh` whenever a model changes, and push the models and the manifest to the hosted repo together ([`Documentation/BACKGROUND-ASSETS.md`](Documentation/BACKGROUND-ASSETS.md)).
- **Gate:** `scripts/gate.sh` — the app-hosted suite on the macOS destination, the CLI suite, Debug + Release on both platforms and the CLI built warning-free, the localization drift check over both String Catalogs (presence *and* translation into all ten shipped languages), and the artifact reads nothing else catches (the App Shortcuts provider actually registering, the bundle ids, which appex is embedded where, a privacy manifest in every shipped bundle, the macOS entitlements, the Release Mac's hardening). **A `.swift` file added since the last `xcodegen generate` is in no target and never compiles — the suite passes having never seen it — so regenerate after adding one and check the test count moved.** **One leg runs the app rather than reading it:** the cold-launch leg installs the Release build onto a simulator that has never held it and fails if a first-ever launch does not reach an interactive UI inside `COLD_LAUNCH_BUDGET` — every other check is blind to a cost paid once on first install, and the leg creates and deletes its own device. `SIM_NAME` points the iOS build leg at your own simulator. The real-model and bench suites are env-gated and off by default; through xcodebuild their env vars need a `TEST_RUNNER_` prefix to reach the test host — e.g. `TEST_RUNNER_SORTFORMER_MODEL_OK=1 xcodebuild … test -only-testing:TranscriptionStudioTests/SortformerRealModelTests`, likewise `TEST_RUNNER_CONCURRENT_BENCH=1 … ConcurrentLoadBench` and `TEST_RUNNER_LUXTTS_MODEL_OK=1 … LuxTtsLiveTests` (real cloned synthesis; needs a voice profile on disk) — run them when touching those paths. Verification audio: `scripts/make-verification-audio.sh`.
- **`transcribe-cli` is live infrastructure — the Jarvis `transcribe` tool shells out to the installed copy (`--serve`, via a 24/7 LaunchAgent).** A change to its flags, output shape, or the pipeline behind it must keep that contract; `scripts/install-serve.sh` rebuilds and refreshes the installed binary (the LaunchAgent runs from the stable app-owned path, never `.build/`), so re-run it after any CLI change and verify end-to-end.
- **The Share extension's source membership stays Foundation-only, forever** (the `SharedItems/` files it compiles) — the share extensions are memory-capped (~120 MB) and must never gain FCTSpeech or Core ML model loading, directly or transitively. The same holds for the widget (`Glance/`) and Background Assets extension memberships.
- FCTFoundation is a sibling checkout at `../FCTFoundation`, granular products only.
- **Live testing signs into the shared FCT account, and its rows sync and outlive the run.** Read `~/Jarvis/projects/shared-test-account.md` before any seed, reset or demo path: a reset behind a required sign-in tombstones rows on every device on the account.
